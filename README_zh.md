# dsh-knowspace

**面向 DeepSeekHarness 的 Agent 原生、本地优先知识基础设施。**

[English](README.md) | [简体中文](README_zh.md)

> **项目状态：开发中 · 公开占位仓库 · 尚未发布公开 Alpha 版本**  
> README 更新日期：2026 年 10 月 12 日。项目目前主要在私有仓库开发；本公开仓库作为官方项目介绍页，暂不提供可安装插件或可供外部审计的完整源码。

`dsh-knowspace` 希望让用户和获得授权的 AI Agent 使用同一套知识资源，同时不把云服务、向量数据库或常驻 AI 进程变成知识的实际拥有者。它的定位是 [DeepSeekHarness](https://github.com/deepseek-ai/deepseek-harness) 插件，而不是独立部署的知识库服务器。

项目长期目标是建立可复用的知识管理、检索、渲染和交互基础设施，让 Agent、Skills、脚本及其他垂直插件可以在其上组合业务能力。

## 为什么开发 KnowSpace？

很多 AI 工作流只是把知识当作一次性的会话上下文，或者交给外部检索服务。KnowSpace 采用不同的设计原则：

- **文件属于用户。** Markdown 笔记与图片保留为可迁移、可直接访问的本地资产。
- **Agent 访问受权限约束。** 按工作区和用户策略授权，不让所有 Agent 默认读取全部知识。
- **离线能力优先。** 阅读、编辑和基础搜索不应依赖网络。
- **按需同步。** 可以通过 WebDAV 在设备间同步受支持的知识资产，不需要部署专用的 KnowSpace 服务端。
- **通用交互能力复用。** 数学公式、知识图表、临时页面和用户输入回传应当成为公共基础设施，而不是每个 Skill 各做一遍。

**设计原则：知识由用户掌控，AI 的介入应当显式、受限且可追溯。**

## 产品能力与规划

### 1. 知识管理：工作区、文件与可选同步

计划支持两种职责不同的工作区：

| 工作区类型 | 行为 |
| --- | --- |
| **本地工作区** | 文件独立保存在当前设备，不会自动同步。 |
| **同步工作区** | 设备上始终保留完整的本地工作副本，联网时可通过 WebDAV 进行双向同步。 |

Markdown 是主要的可迁移知识格式。默认的**同步白名单**仅包括 `.md`、`.jpg` 和 `.png`；PDF、视频、音频、3D 文件、可执行内容及原生图表源文件不会作为原件自动上传。富媒体可保留在本地；用户明确要求从富媒体提炼出的 Markdown 是**独立知识资产**，不必始终依赖其原始素材。

数据管理强调可见的变更记录、Diff、冲突保护、非破坏性处理和异常恢复，而不是发生冲突时静默覆盖。

### 2. 知识检索：本地优先与可信证据

KnowSpace 以受工作区权限约束的文本检索为基础。后续增强会借鉴 Greb 式候选召回与排序思想，但**不会默认调用 Greb 云端 API，也不会强制依赖任何第三方 MCP 服务**。

预期的检索链路如下：

```text
已授权的知识工作区
        |
本地文本与文件候选召回
        |
权限过滤、排序与可选融合
        |
可追溯的原文证据片段
        |
Agent 回答或用户检索结果
```

在适用环境下，可以选择 ripgrep 或 SQLite FTS5 作为本地加速组件；没有这些依赖时仍使用进程内扫描。Embedding 与重排属于后续可选增强，基础知识库不要求必须安装向量数据库。

### 3. 内容渲染：Markdown、数学与安全预览

共享渲染层计划提供：

- Markdown 笔记、表格、代码块和图片引用。
- LaTeX 风格数学公式与适合学习场景的数学排版。
- 受限的知识内容预览与 Agent 工具结果展示。
- 在 Host 可执行隔离、授权和资源限制时，提供临时交互式内容。

不可信 HTML/JavaScript 不能因为出现在笔记或预览区域，就获得 Host、文件系统或 Agent 的权限。**静态 Markdown 渲染与可执行交互页面属于两条不同的安全边界。**

### 4. 交互基础设施：Agent 与用户双向协作

除静态阅读外，KnowSpace 还将提供由用户明确触发的交互流程：Agent 生成临时页面或表单，用户填写信息、上传图片或进行手写输入，再通过受控桥接将结构化结果交还给获得授权的 Agent。

适用示例包括数学手写答题、学习练习、科研审阅表单，以及 Skill 生成的辅助工具。这些都是基础设施的应用示例，**不意味着核心插件要内置一整套考研系统或科研业务软件**。

### 5. 知识图表：可编辑结构化图，而非写实生图

规划中的绘图能力将把流程图、思维导图和系统架构图表示成**可编辑的矢量或结构化资产**，不依赖生成写实图片的扩散模型。

既定方案是参考并有选择地适配 [fourzkw/dsh-drawai](https://github.com/fourzkw/dsh-drawai) 中适合的 `.drawio` 编解码、图模型和布局实现，实际复用前必须固定上游版本并完成许可审计。Host 授权、工作区及 Agent 工具仍由 KnowSpace 自己实现。原生 `.drawio` 源文件默认仅保存在本地；用户明确导出的 `.png` 可以作为独立知识资产，遵循既有同步规则。

**这项图表集成已经完成设计裁决，但尚未发布实现。**

## 目标架构

```text
DeepSeekHarness
  |-- 侧边栏与知识界面
  |-- Agent Tools（按权限访问）
  |-- Skills 与其他插件
  |
  `-- dsh-knowspace 插件
       |-- Knowledge Core：工作区 / 资产 / 变更 / 权限
       |-- Retrieval Core：本地检索 / 证据定位
       |-- Rendering Core：Markdown / 数学 / 安全预览
       |-- Interaction Core：临时页面 / 用户提交
       |-- Diagram 能力：可编辑结构化图表（规划中）
       |
       |-- 本地文件与本地索引
       `-- 可选 WebDAV 同步（仅同步白名单文件）

无需独立 KnowSpace 服务端或强制云向量数据库。
```

上图是**目标架构**，并不表示其中所有组件都已经实现或公开发布。

## 隐私与安全边界

- 普通浏览、索引与同步不会在后台擅自调用模型、总结笔记或制作用户画像。
- Agent 可读取的工作区、私密工作区和禁止 Agent 读取的工作区严格区分。
- Agent 写入和交互提交必须具有有效授权；身份无法确认时不得默认放行。
- 文件修改、冲突和失败状态应当可查看、可追溯且能够恢复。
- 同步不能静默上传仅限本地的富媒体原件、`.drawio` 或任意可执行文件。
- 新检索与绘图模块不得未经评审、迁移与回归测试就替换已有存储同步协议。

以上属于**架构原则和发布验收要求**，不是声称所有安全场景均已通过独立审计。

## 与其他项目的关系

KnowSpace 可以配合 [dsh-agent-team-presets](https://github.com/bloodarea/dsh-agent-team-presets) 使用，但彼此**没有强制依赖**。后者负责配置与复用 Agent Team，决定“哪些 Agent 执行任务”；KnowSpace 则希望提供“获得授权的 Agent 可以读取、修改、检索和展示哪些知识”的基础设施。

项目会借鉴 DeepSeekHarness 生态及其他社区的公开实现。技术选型区分三类路径：**直接使用依赖、选择性复用源码、借鉴思想后原生实现**。在 README 中提到某个项目，不代表已经引入其源码。

相关参考包括 [DeepSeekHarness](https://github.com/deepseek-ai/deepseek-harness)、[dsh-drawai](https://github.com/fourzkw/dsh-drawai)、[ripgrep](https://github.com/BurntSushi/ripgrep)、[SQLite FTS5](https://www.sqlite.org/fts5.html)、[markdown-it](https://github.com/markdown-it/markdown-it) 和 [KaTeX](https://github.com/KaTeX/KaTeX)。未来如实际分发第三方代码，将逐项核查许可证并保留必要的版权声明和致谢。
